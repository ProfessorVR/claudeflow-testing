## What Was Built

### The ICPPipelineAdapter (the core architectural decision)
The god-write CLI has 56+ fixes and powerful features (multi-step drafting, rolling context, investigateV1, author scrubbing, chunk trimming, attention reordering) that are all **private methods** on `WritePipelineOrchestrator`. The ICP dashboard had none of these.

We couldn't import the private methods directly, and we couldn't modify the CLI (Dalton's hard constraint). So we built an adapter that **re-implements the 5 critical private methods as standalone functions** and imports all public utilities (ProseSanitizer, author-scrubber, domain-config, gold-standard-config, prompt-builder, etc.) read-only.

The adapter implements an **event-driven state machine** — each API call reads session state, runs utilities, writes results back. No suspended processes. The session object IS the pipeline state.

### Rolling Context with Tiered Compression
Sections generate one at a time. Recent sections (WARM zone, last 2) appear as full text. Earlier sections (COLD zone) are compressed to ~50-word Haiku summaries. Dynamic token budget check at 12K ceiling with auto-downgrade cascade.

### WebSocket Streaming + Abort
- Express server creates `WebSocketServer` on same HTTP server at `/ws/icp`
- Dashboard auto-connects, subscribes to session events
- `section-complete` events stream in real-time during rolling context generation
- Abort travels over WS — client sends `{type: 'abort'}`, server calls `AbortController.abort()`, adapter catches at next section boundary, saves `PARTIALLY_GENERATED`
- Browser disconnect does NOT abort — intentional, to avoid wasting API spend on accidental disconnects

### Dashboard UI
- 12 checkbox controls for pipeline features
- 2 dropdowns (grounding strictness, cost tier)
- Advanced Settings collapsible with 8 tunable parameters
- Investigation panel showing v1 analysis results
- Generation Progress panel with Cancel button and real-time WS event rendering
- Quality Gates enhanced with active execution + SoNA feedback

## Red Flags / Concerns

1. **Nothing is committed.** This is the biggest risk. ~2,700 lines of new/modified code sitting in the working tree. If the machine dies, the backups directory is also uncommitted. Dalton should commit or stash before shutdown.

2. **The 5 re-implemented private methods** (investigateV1, trimChunkContent, reorderChunksForAttention, enforceSourceDiversity, validateRetrievalCoverage) are copies of CLI logic. When Fix 57+ lands in the CLI, these copies need updating in parallel. This is a known trade-off, documented in the implementation report.

3. **WebSocket streaming is wired but not end-to-end tested with a real generation.** The WS server starts, clients connect, events emit — but we haven't done a live rolling context generation through the dashboard to see sections stream in real-time. That requires ChromaDB + embedding server + Anthropic API all running.

4. **202 untracked files** is a lot of cruft. Many are `.pre-*-bak` files from prior sessions, `__pycache__` directories, and analysis outputs. Not harmful but noisy.

5. **The adapter's `generate()` method stores chunks as `(session as any)._adapterChunks`** — a transient field not in the ICPSession type. This is a typing escape hatch that works but is ugly. The proper fix is converting QuoteSpan[] to ContextChunk[] at the API layer, but that's a Phase 5 polish item.
