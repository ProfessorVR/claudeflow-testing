## 2. The 6-point coordination protocol (locked at Phase 4 close)

Each item-25 sub-session executes per §7.6 codification-decomposition framework Phase 6, with these 6 cross-sub-session coordination requirements:

### 2.1 Mandatory anchor verification (Phase 1 of §7.6 per sub-session)

Each sub-session opens with anchor verification matching the SITREP anchors of the predecessor sub-session:
- Validator OK
- Holdout md5 unchanged
- Dev jsonl line count
- Drift-log entry count
- §8.1 counter
- Latest backup recency

If anchors mismatch: HALT and re-establish state before sub-session work begins.

### 2.2 Mandatory predecessor handoff consumption

Each sub-session consumes any active coordination handoffs from predecessor sub-sessions before its own sub-task work begins:

| Predecessor → Successor | Handoff |
|---|---|
| item-25a A.2 → **item-25d MANDATORY OPENING** | dev-21 resemblance + dev-22 multi-cross-author PRESERVE-WITH-FLAG dispositions reconciled before D.2/D.5 codification |

### 2.5 Per-decision review discipline (§8.5 Format A)

Every codification proposal is rendered in §8.5 Format A:
- Proposal statement
- Numbered Q-list (decision points requiring user resolution)
- Concern A-N parallel structure as PART of Format A (when applicable)
- HALT-FOR-USER-REVIEW reserved for: pre-codification anchor mismatch / inadvertent specification discrepancy / scope expansion beyond authorized sub-task

Format B (truncated minimal-Q form) restricted to non-codification proposals (e.g., resource-planning discussion).

Pushback-re-presents-in-Format-A: if user raises a Q outside the prescribed Q-list, codification halts and Q is mapped into Format A Q-list before proceeding.
