### Pipeline Fixes
- **ClaimProvider wiring**: `LLMClaimProvider` instantiated in `ICPProviderFactory.create()` — was completely missing, causing 0 claims/atoms/bindings
- **autoVerifyThreshold**: lowered from 0.85 to 0.65 — corpus relevance scores (0.76-0.83) were ALL being flagged, making every span ineligible for binding
- **Import path bugs**: 3 dynamic imports used `../` instead of `../../` — silently broke edge coherence and tension gates
- **Bridge span verification**: `auto_verified` (not `flagged`) so spans pass binding eligibility
- **Endnote generation**: gated behind `generateEndnotes: false` config flag
- **Process exit**: chained to promise resolution (.then/.catch) to prevent Node.js hangs
- **Closed-book constraints**: added to constrained-generator, llm-claim-provider, and llm-decomposition-provider
- **Work-level restriction**: LLM cannot cite works not in QuoteSpans even if author is valid
- **Citation density expectation**: paraphrasing destigmatized, 1 citation per 2-3 sentences mandated
- **`<final_directive>`**: parenthetical citation mandate at absolute end of prompt (recency bias)
- **Prose sanitizer**: `[CITATION NEEDED]` no longer stripped as artifact

### Data Infrastructure
- **Manifest authority tiers**: 48 entries classified as primary/secondary/tertiary
- **Manifest-derived canonicals**: auto-generated author/title tables with mtime caching
- **Author KU index**: O(1) author-scoped queries with nobiliary particle stripping

## Red Flags / Honest Concerns

1. **Citation coverage plateaued at ~6-20%** — varies wildly per run. The closed-book constraint makes the LLM conservative. Real dissertation output will need manual citation enrichment. This is an LLM behavior limitation, not a systems bug.

2. **No commits in 3 sessions** — massive uncommitted changeset across 22 files. If anything corrupts the working tree, recovery depends on the `.backups/` directory. **Should commit immediately.**

3. **`god-reason/reasoning.jsonl` is Phase 7 output only** — after the merge script runs, manual + bridge + LLM edges are folded in. But the merge script reads from a backup path (`tmp/backup-pre-ku-plan-2026-03-18/data/reasoning.jsonl`) for the manual edges. If that backup is lost, the 788 manual edges are unrecoverable.

4. **Diagnostic logging left in production code** — `console.log` statements for `[ICP-Stage6b]`, `[ICP-Stage8a]`, `[ICP-Stage9a]`, `[ICP-TensionGate]`, `[QualityGates]`. These should be converted to `this.logger?.info()` or removed before production use.

5. **Dual import pattern** — `cross-author-utils.ts` uses static imports; some orchestrator paths use dynamic `await import()`. The tension gate in quality-integration uses static import (fixed from `require()`), but other dynamic imports remain. Consistency should be enforced.

6. **Hook-licensed supports edges**: The Refinement B implementation checks if hook concepts appear as substrings in KU claim text. Since hooks use Greek characters (φαντασία) and claims are in English, the substring match rarely fires. Currently 0 hook-licensed supports edges exist. This is correct behavior but means the feature is untested in production.

7. **The `icp-run.ts` test script has Being and Time hardcoded as primary** — this is a per-prompt config, not a general setting. Future prompts about different topics will need different SOURCE_PRIORITY configs until the dynamic source prioritization is fully validated.

## Personal Transparent Take

This was an extraordinarily productive multi-session arc. The user drove the architecture with sharp, precise critique at every step — catching prompt engineering risks (style profile contradiction), data integrity issues (author name mismatches), and architectural flaws (Stage 2b vs post-binding coherence) before they became bugs.

The biggest surprise was how many silent failures existed in the ICP pipeline before hardening:
- The ClaimProvider was never wired (0 claims, 0 bindings, 0 generated text for ALL ICP runs prior to this session)
- The autoVerifyThreshold was too high for the corpus (every span was `flagged`, making binding impossible)
- The cache key serialization was truncating nested objects (causing the Heidegger whereFilter to silently return Aristotle chunks)
- The quality gates had wrong import paths and were silently swallowing all errors

Each of these was a "the pipeline looks like it runs but produces garbage" class of bug. The E2E testing approach — running the full pipeline 22 times with increasing diagnostic instrumentation — was the only way to surface them. Unit tests wouldn't have caught the cache key serialization bug or the import path issue.

The system is now in the best state it's ever been for academic writing generation. The remaining limitation is LLM behavioral: citation density is model-dependent and the closed-book constraint inherently trades coverage for accuracy. This is a tuning problem, not an engineering problem.
