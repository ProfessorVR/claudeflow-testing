## Red Flags

1. **Nothing is committed.** All work from this session is in the working tree. A single `git checkout .` would destroy everything. The backups exist but the primary state is uncommitted.

2. **Voice monotonicity hasn't moved (0.372).** The threshold calibration improved label agreement from 15% to 57.5%, but the underlying ranking is unchanged. Voice measures authorial intention — a fundamentally harder problem than any heuristic can solve.

3. **Opacity is at 0.192 and is honestly stuck.** Revised target is 0.35. The AT/THROUGH distinction is a reader-response phenomenon. Neither heuristics, POS, clause parsing, nor LLM-as-judge improved it.

4. **Parataxis is at 0.378 despite the clause parser.** Corrective depth reached 0.405 (+0.027) but below the +0.05 promotion gate. The 40-passage gold set may be too small to validate parataxis improvements — next move should be a small parataxis-specific annotated set, not more coefficient searching.

5. **The calibration test suite has 5 hard-enforcement failures** on the original aspirational targets (voice, parataxis, opacity monotonicity). These targets are formally revised in `plans/lanham-revised-targets.md` but the test file still has the old assertions. Should be updated.

## Honest Assessment

This session accomplished more than any previous Lanham work: +0.142 on nounVerb, +0.163 on periodic, +0.099 on register, +42.5% on voice agreement. The clause parser is real infrastructure that produces correct clause graphs at 3ms/passage. The two-layer controller is a mature architectural pattern that prevents regressions.

But the system has also reached a genuine plateau on three axes. Parataxis and opacity are at their heuristic ceilings. Voice ranking is stuck. These are not bugs — they are limits of what regex/POS/clause heuristics can measure about prose. The next meaningful improvement on these axes requires either human-annotated calibration data or a fundamentally different measurement approach.

The most valuable thing about this session isn't any single metric improvement — it's that the system now **knows what it's good at and what it isn't**, and the architecture prevents overconfident features from degrading production output.
