**Build 32** = build 30 minus Immersive Mode, plus the fixes below.

**Windows Shipping never benchmarked — fixed.** `FApp::IsInstalled()` is hard-coded true for Shipping desktop builds,
so Shipping saves to `%LOCALAPPDATA%\awsTutorial\Saved` while Development saves beside itself. That directory held an
options save from July 2025, and the tuner's gate read "menu save present + never tuned" as "the player chose these",
skipping forever. Gate now keys on `TunedVersion` alone; `TuneVersion` bumped 1 → 2 so already-tuned installs re-tune
once. Verified on CHIMERA with the real stale save in place.

**macOS resolution list — engine patched.** `MetalRHI.cpp` divided every `CGDisplayMode` by the Retina backing scale a
second time, so the menu could only offer half the panel (1440 × 932 for a 2880 × 1864 display) and native could never
be selected. One line removed; the row now shows true pixel resolutions and the tuner picks native. **Operator
confirmed.**

**macOS click offset — mitigated, not solved.** In either fullscreen mode UE caches `[NSScreen visibleFrame]` (screen
less the menu bar) as the window size and nothing corrects it, so clicks land ~1 cm from the pointer. Windowed mode is
correct; the game is now kept windowed at startup. See §5 for what is still wrong.

**Two Core Audio memory bugs fixed.** Both the project's `AudioOutputSelectorSubsystem` and the voice plugin's
`EVCCaptureCore_Mac.cpp` sized a buffer from a size query, then passed that *stale* size to
`AudioObjectGetPropertyData` as the capacity. If the device list or a device's stream configuration changed in
between, Core Audio wrote past the allocation — one extra `AudioBuffer` puts a small integer over a neighbouring
heap object's pointer field, and an unrelated `free()` dies later. Both now allocate with slack, pass the true
capacity, retry if the payload grew, and clamp the read. This is the change that appears to have stopped the
mid-session crashes.

## 5. Open problems, ranked

### 5.1 The app crashes on quit — the top item

Every crash still on disk of this family has the same stack:

```
Fatal error: [MallocBinned2.cpp] [Line: 1157 or 1322], SIGSEGV at 0x3
  FMallocBinned2::GetAllocationSizeExternal ← FMallocPoisonProxy::Free ← FMemory::Free ← operator delete[]
  ← AudioDSP!VAD3ConfigurationInterface_DecodeFull ×3
  ← AudioDSP!AUAnomalyDetectionFactory ×3
  ← AudioToolboxCore!AudioComponentInstanceDispose ← DSPGraph::AUBox::close ← DSPGraph::Graph::~Graph
```

The 2026-09-20 16:24 soak ran **70 minutes 26 seconds** of video with no trouble and then crashed **at the moment the
operator quit**, at 17:35:23. The earlier "19-minute" control-run crash was also at a manual quit. So the current
reading is: *mid-session* corruption crashes appear to be fixed; what remains is a crash in Apple's audio-unit
teardown when the VoiceProcessingIO graph is destroyed at shutdown.

Consequences worth stating: the game never reaches `LogExit: Exiting`, so **anything saved on exit may be lost** —
including `GameUserSettings.ini` and the options save. That explains a config override disappearing earlier in the day.

Where to look next, in order:
1. `Plugins/UltimateMultiplayerServicesPlugin/Source/EmbeddedVoiceChat/Private/Mac/EVCCaptureCore_Mac.cpp:~532` — a
   stack `AudioBufferList List;` with `mNumberBuffers = 1` handed to `AudioUnitRender`. `AudioBufferList` declares
   `mBuffers[1]`, so a de-interleaved format with more than one channel writes past the object. Same class of bug as
   the two already fixed, not yet addressed.
2. Whether the plugin stops and uninitialises the audio unit before `AudioComponentInstanceDispose`.
3. Pragmatic workaround if the above fails: stop using the macOS VoiceProcessingIO AEC backend, so the graph is never
   built or destroyed. The log names the backend at startup: `[VoiceChat] Capture back-end: macOS VoiceProcessingIO (AEC)`.
4. It is vendor code — worth reporting upstream with these stacks either way.

### 5.2 macOS click alignment is close but not exact

Windowed is correct enough to use and was confirmed by the operator, but with the window code disabled the operator
described login and menu as "closer but still not perfect". The residual error tracks how far the applied resolution
is from the display. Fullscreen is worse and **cannot be applied at startup at all** — every attempt (1440 × 932,
2880 × 1836, 2880 × 1790) rendered into the top-left corner with dead input. Fullscreen only behaves when the options
menu puts the game there after login, and then `gfx.MacWindowRepair 2` trims it correctly.

Known-good values measured on this Mac: fullscreen `2880x1790f` applied from a settled state, alignment correct.

### 5.3 The Dock still covers the video player controls

The window is *sized* right (2880 × 1682 ≈ the usable 1676) but UE **centres** it (`WindowPosX/Y = -1`), leaving
~45 pt top and bottom where the Dock needs 60. The fix is to move the window, not resize it: `SWindow::MoveWindowTo`
to the work-area origin (68 px down) with height 1676. Coded but **not implemented** — the engine's own
`FDisplayMetrics` is unreliable here (it reports a 28 px work-area top and 56 px total against the OS's 68 and 188),
so the geometry should come from measured constants exposed as cvars.

### 5.4 Defects found by adversarial review, not yet fixed

From `GraphicsAutoTuneSubsystem` (full list in the review, summarised here):

* **`SetRow` failures are recorded as success.** `Commit` decides success from whether the save *wrote*, not whether
  anything was *applied*, then writes `TunedVersion` — an install can be marked tuned with nothing applied and never
  tune again. Fix: accumulate `bAllRowsSet &= SetRow(...)`.
* The Mac window watcher has three detector bugs: the cooldown swallows changes permanently, same-value
  re-applications are invisible (the login case it was written for), and the 3 s startup delay never applies.
* `MacRepairCount` exhausts after 8 repairs, silently and permanently.
* The repair can fire *during* a benchmark and poison the frame-time samples.
* `Abort` never records an outcome, so a Shipping build cannot be diagnosed from the ini.
* `r.VSync` / `r.ScreenPercentage` are set at console priority, which permanently blocks `GameUserSettings` and
  scalability from changing them for the rest of the process.
* The Mac repair is not gated by `-NoGraphicsAutoTune` or `GIsEditor`.

Given 5.1 and 5.2, the simplest resolution for several of these is to **apply the window change once at startup and
delete the watcher entirely**.

## 6. Facts that cost time to learn — do not rediscover them

* A packaged build **ignores `-ini:` cvar overrides on the command line**. Use `[SystemSettings]` in
  `<GameDir>/awsTutorial/Saved/Config/<Platform>/Engine.ini`, or `-ExecCmds="..."` on the command line — but the
  config file is **rewritten on a clean exit**, so an override placed there does not survive a normal quit.
* `r.setres WxH` with **no suffix keeps the current window mode** (`GameViewportClient.cpp:3870`). `w` = windowed,
  `wf` = windowed fullscreen, `f` = fullscreen. A missing `w` is why a window "round-trip" did nothing for hours.
* Slate's screen space on macOS is **backing pixels**, so `r.setres` there takes pixel sizes (2880 × 1682), not points.
* `run_probe.ps1` on CHIMERA fails silently if `-GameArgs` is empty — pass something like `-nosplash`.
* The probe's synthetic mouse clicks do not reach UMG; button bindings must be exercised by console or by hand.
* The tuner cannot reach the options menu before the Cognito login, so no automated run can complete a benchmark.
* UE keeps only **10 backup logs**; two crash logs were lost to rotation today. Copy a crash log off the Mac before
  relaunching.
* macOS screen-recording permission is granted, so `screencapture -x` works over ssh; System Events/AppleScript window
  queries hang.
